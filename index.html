// What it does

Debugging, minus the boilerplate

Drop a widget onto your screen and populate it with live stats and controls — all from a single require call.

[ ▸ ]

Chainable API

Every method returns the widget, so you can wire up an entire panel in one expression without intermediate variables.

[ ~ ]

Live Labels

Pass a callback and Widgengine polls it for you — either every 0.5 s or on RenderStepped for frame-perfect data.

[ ⬡ ]

Sub-Containers

Group related buttons under a labelled section. Buttons inside containers auto-flow into rows of two.

[ ↔ ]

Draggable & Collapsible

Widgets ship with built-in UIDragDetector and a dropdown toggle — no extra setup required.

[ ✦ ]

Icon Buttons

Pass any rbxassetid:// as the button name and it renders as a centred icon image instead of text.

[ ⚠ ]

Client-Only Safety

Guards itself from server execution and warns on duplicate widget names — keeping your output clean.

// Getting started

Up in three steps

Widgengine works wherever a LocalScript (or a Script with RunContext = Client) has access to it.

01

Download & place the module

Download the .rbxm and drag it into your Roblox place. ReplicatedStorage is recommended so the client can reach it.

↓ Download Widgengine_v1_1.rbxm
02

Require & create a widget

Inside any LocalScript, require the module and call widgengine.New() with your panel's title. Store the result if you plan to add sub-containers later.

local ReplicatedStorage = game:GetService("ReplicatedStorage")
local widgengine = require(ReplicatedStorage.Widgengine)

local myWidget = widgengine.New("Debugger")
03

Add labels and buttons

Chain :AddLabel and :AddButton calls. For sub-containers, call :AddContainer on the stored widget reference — see the full example below.

myWidget:AddLabel("FPS", function()
    return math.floor(1 / currentDelta)
end, false):AddLabel("Ping", function()
    return Round(Players.LocalPlayer:GetNetworkPing() * 1000, 2) .. " ms"
end)
// NOTE

Labels update automatically. Supply the callback once and Widgengine handles polling. Pass false as the third argument to use a 0.5 s loop instead of RenderStepped — better for cheap stats like ping.

// Widgengine

widgengine.New (WidgetTitle: string) → Widgengine static ▾

Creates a new draggable, collapsible widget panel and adds it to the player's ScreenGui. Returns the widget object for chaining. Calling this on the server or with a duplicate title emits a warning and returns nil.

ParameterTypeDescription
WidgetTitlestringUnique name shown in the widget's title bar and used as the key in widgengine.Widgets.
Returns Widgengine — the widget instance (chainable).
:AddLabel (name, callback, useRunService?) → Widgengine method chainable ▾

Adds a full-width two-column row: a left-aligned name and a right-aligned value that refreshes automatically. A label always breaks any open button row, so subsequent buttons start a new row.

ParameterTypeDescription
namestringStatic label shown on the left side.
callback() → stringCalled repeatedly. The return value is displayed on the right side.
useRunServiceboolean?Defaults to true on the top-level widget — fires every RenderStepped. Pass false for a 0.5 s polling loop.
Returns Widgengine — the widget instance (chainable).
:AddButton (name, callback) → Widgengine method chainable ▾

Adds a full-width button to the widget with built-in hover and press colour tweens. If name starts with rbxassetid://, the text is hidden and a centred ImageLabel is rendered instead.

ParameterTypeDescription
namestringButton label text, or an rbxassetid:// URL to render an icon.
callback() → nilFired when the button is activated.
Returns Widgengine — the widget instance (chainable).
:AddContainer (containerName: string) → SubContainer method ▾

Inserts a visually distinct sub-section with its own header label and semi-transparent background. Returns a SubContainer — use its methods to populate it. Because the return type changes, you must store the parent widget in a variable first if you want to keep adding items to it after calling :AddContainer.

ParameterTypeDescription
containerNamestringHeader text displayed above the grouped content.
Returns SubContainer — a new sub-container instance (not the parent widget).

// SubContainer

:AddButton (name, callback) → SubContainer method chainable ▾

Adds a button to the sub-container. Buttons are auto-arranged into rows of up to two. When a row is full, a new one is created. Supports rbxassetid:// icons identically to the top-level :AddButton.

ParameterTypeDescription
namestringButton label or rbxassetid:// icon URL.
callback() → nilFired on button activation.
Returns SubContainer — chainable.
:AddLabel (name, callback, useRunService?) → SubContainer method chainable ▾

Adds a live label row inside the sub-container. Defaults useRunService to false (0.5 s poll) unlike the top-level version.

ParameterTypeDescription
namestringStatic title shown on the left.
callback() → stringReturns the value displayed on the right.
useRunServiceboolean?Defaults to false. Set true for per-frame updates.
Returns SubContainer — chainable.

// Static Properties

widgengine.Widgets { [string]: WidgetData } static ▾

A shared table keyed by widget title that stores every created widget's internal data. Useful for accessing a widget's UI frame or Dropped state from outside the creation scope. Direct mutation is not recommended.

Type { [string]: { UI: Frame, Dropped: boolean, Connections: {}, _layoutOrder: number } }

// Examples

Full example

A complete LocalScript reproducing both widgets from the screenshot above.

// localscript — debugger + information widgets

local Players          = game:GetService("Players")
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local RunService        = game:GetService("RunService")
local widgengine        = require(ReplicatedStorage.Widgengine)

local currentDelta = 0

local function Round(num, places)
    local mult = 10 ^ places
    return math.floor(num * mult + 0.5) / mult
end

-- Debugger widget
local myWidget = widgengine.New("Debugger")
myWidget:AddLabel("FPS", function()
    return math.floor(1 / currentDelta)
end, false):AddLabel("Ping", function()
    return Round(Players.LocalPlayer:GetNetworkPing() * 1000, 2) .. " ms"
end)

-- Information widget
local myOtherWidget = widgengine.New("Information")
    :AddLabel("Parts", function()
        return #workspace:QueryDescendants("BasePart")
    end)
    :AddLabel("Models", function()
        return #workspace:QueryDescendants("Model")
    end)

-- "Utils" sub-container
myOtherWidget:AddContainer("Utils")
    :AddButton("Reset", function()
        Players.LocalPlayer.Character.Humanoid.Health = 0
    end)
    :AddButton("Summon", function()
        Instance.new("Part", workspace.Camera).Position = Vector3.new(0, 100, 0)
    end)
    :AddButton("rbxassetid://11768945414", function()
        workspace.Camera:ClearAllChildren()
    end)

-- "MyContainer" sub-container
myOtherWidget:AddContainer("MyContainer")
    :AddButton("Test",  function() print("Click!") end)
    :AddButton("Test2", function() print("Click")  end)
    :AddButton("Test3", function() print("Click")  end)
    :AddButton("Test4", function() print("Click")  end)
    :AddButton("Test5", function() print("Click")  end)

-- Track delta for FPS label
RunService.PreRender:Connect(function(dt)
    currentDelta = dt
end)
// KEY PATTERN

:AddContainer returns the SubContainer, not the widget. Store the widget in a variable (myOtherWidget) and call each :AddContainer on that variable separately — don't try to chain containers off each other or back onto the widget from a container's return value.
