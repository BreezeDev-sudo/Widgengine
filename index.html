Widgetengine

Build floating debug panels inside Roblox in seconds. Labels, buttons, containers — wired up with a fluent, chainable API.

Get Started → Download .rbxm

// live preview in Roblox Studio

// What it does

Debugging, minus the boilerplate

Drop a widget onto your screen and populate it with live stats and controls — all from a single require call.

[ ▸ ]

Chainable API

Every method returns the widget, so you can wire up an entire panel in one expression without intermediate variables.

[ ~ ]

Live Labels

Pass a callback and Widgengine polls it for you — either every 0.5 s or on RenderStepped for frame-perfect data.

[ ⬡ ]

Sub-Containers

Group related buttons under a labelled section. Buttons inside containers auto-flow into rows, two per row.

[ ↔ ]

Draggable & Collapsible

Widgets ship with built-in drag detection and a dropdown toggle — no extra setup needed.

[ ✦ ]

Icon Buttons

Pass any rbxassetid:// as the button name and it renders as a centred icon image instead of text.

[ ⚠ ]

Client-Only Safety

The module guards itself from server execution and warns on duplicate widget names, keeping your output clean.

// Getting started

Up in three steps

Widgengine works wherever a LocalScript (or a Script with RunContext = Client) has access to it.

01

Import the module

Download the .rbxm and drag it into your Roblox place. Place Widgengine anywhere the client can require it — ReplicatedStorage is ideal.

↓ Download Widgengine_v1_1.rbxm
02

Require & create a widget

Inside any LocalScript, require the module and call Widgengine.New() with your panel's title.

local Widgengine = require(game.ReplicatedStorage.Widgengine)

local widget = Widgengine.New("Debugger")
03

Add labels and buttons

Chain as many components as you need. The widget auto-sizes to fit.

widget
  :AddLabel("FPS", function()
      return tostring(math.round(1 / game:GetService("RunService").RenderStepped:Wait()))
  end)
  :AddLabel("Ping", function()
      return tostring(game:GetService("Stats").Network.ServerStatsItem["Data Ping"].Value) .. " ms"
  end)
  :AddButton("Reset", function()
      game.Players.LocalPlayer.Character:BreakJoints()
  end)
// NOTE

Labels update automatically. You don't call :AddLabel in a loop — just supply the callback once and Widgengine handles the polling.

API

// Widgengine

Widgengine.New (WidgetTitle: string) → Widgengine static ▾

Creates a new draggable, collapsible widget panel and adds it to the player's ScreenGui. Returns the widget object for chaining. Calling this on the server or with a duplicate title emits a warning and returns nil.

ParameterTypeDescription
WidgetTitlestringUnique name shown in the widget's title bar. Also used as the key in Widgengine.Widgets.
Returns Widgengine — the widget instance (chainable).
:AddLabel (name, callback, useRunService?) → Widgengine method chainable ▾

Adds a two-column row: a left-aligned name and a right-aligned value that refreshes automatically by invoking your callback. The label spans the full widget width and always breaks the button row, starting a new row for any subsequent buttons.

ParameterTypeDescription
namestringStatic label shown on the left side of the row.
callback() → stringCalled repeatedly. The returned string is displayed on the right side.
useRunServiceboolean?Defaults to true. When true the callback fires every RenderStepped (every frame). Set to false for a 0.5 s polling loop — better for cheap stats like ping.
Returns Widgengine — the widget instance (chainable).
:AddButton (name, callback) → Widgengine method chainable ▾

Adds a full-width button to the widget. The button has hover and press colour tweens built in. If name starts with rbxassetid:// the text is hidden and a centred ImageLabel is rendered instead, letting you use any Roblox asset as an icon.

ParameterTypeDescription
namestringButton label text, or an rbxassetid:// URL to render an icon.
callback() → nilFired when the button is activated (clicked or tapped).
Returns Widgengine — the widget instance (chainable).
:AddContainer (containerName: string) → SubContainer method ▾

Inserts a visually distinct sub-section with its own header label and a semi-transparent background. Returns a SubContainer rather than the parent widget — use the SubContainer methods to populate it. To add more items to the parent widget after calling :AddContainer, store the widget reference beforehand.

ParameterTypeDescription
containerNamestringHeader text shown above the grouped content.
Returns SubContainer — a new sub-container instance.

// SubContainer

:AddButton (name, callback) → SubContainer method chainable ▾

Adds a button to the sub-container. Buttons are auto-arranged into rows of up to two. When a row is full a new one is created automatically. Supports rbxassetid:// icons exactly like the top-level :AddButton.

ParameterTypeDescription
namestringButton label text or an rbxassetid:// icon URL.
callback() → nilFired on button activation.
Returns SubContainer — chainable.
:AddLabel (name, callback, useRunService?) → SubContainer method chainable ▾

Adds a live-updating label row inside the sub-container. The label always breaks the current button row, just as it does at the top level. Defaults useRunService to false (0.5 s poll) rather than RenderStepped.

ParameterTypeDescription
namestringStatic title shown on the left.
callback() → stringReturns the value to display on the right.
useRunServiceboolean?Defaults to false. Set true for per-frame updates.
Returns SubContainer — chainable.

// Properties

Widgengine.Widgets { [string]: WidgetData } static ▾

A shared table keyed by widget title that stores every created widget's data. Useful for accessing a widget's UI frame or its Dropped state from outside the creation scope. Direct mutation is not recommended.

Type { [string]: { UI: Frame, Dropped: boolean, Connections: {}, _layoutOrder: number } }

// Examples

Full examples

Copy-paste ready. Drop inside a LocalScript and adjust paths.

// complete debugger widget

local RunService  = game:GetService("RunService")
local Stats       = game:GetService("Stats")
local Widgengine  = require(game.ReplicatedStorage.Widgengine)

local fps = 0
RunService.RenderStepped:Connect(function(dt)
    fps = math.round(1 / dt)
end)

Widgengine.New("Debugger")
    :AddLabel("FPS", function() return tostring(fps) end, false)
    :AddLabel("Ping", function()
        return tostring(math.round(
            Stats.Network.ServerStatsItem["Data Ping"].Value
        )) .. " ms"
    end, false)

// widget with sub-containers and icon buttons

local Widgengine = require(game.ReplicatedStorage.Widgengine)
local Players    = game:GetService("Players")
local lp         = Players.LocalPlayer

local info = Widgengine.New("Information")

-- top-level labels
info
    :AddLabel("Parts", function()
        return tostring(#workspace:GetDescendants())
    end, false)
    :AddLabel("Models", function()
        local n = 0
        for _, v in workspace:GetChildren() do
            if v:IsA("Model") then n += 1 end
        end
        return tostring(n)
    end, false)

-- "Utils" sub-container with icon + text buttons
info:AddContainer("Utils")
    :AddButton("Reset",   function() lp.Character:BreakJoints() end)
    :AddButton("Summon",  function() --[[ teleport logic ]] end)
    :AddButton("rbxassetid://12345678", function() --[[ broom icon ]] end)

-- "MyContainer" sub-container
info:AddContainer("MyContainer")
    :AddButton("Test",  function() print("Test")  end)
    :AddButton("Test2", function() print("Test2") end)
    :AddButton("Test3", function() print("Test3") end)
    :AddButton("Test4", function() print("Test4") end)
    :AddButton("Test5", function() print("Test5") end)
// TIP

:AddContainer returns the SubContainer, not the widget. If you need to keep adding items to the parent widget after a container, store the widget in a variable first and call the methods on it separately — do not chain :AddContainer(...):AddButton(...) and then continue chaining on the widget.
